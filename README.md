# AI Agent Tutorial

A hands-on tutorial for building AI agents in Python with [Agentspan](https://pypi.org/project/agentspan/) and Google Gemini (`gemini-2.5-flash`). Each script adds a new concept on top of the previous one: tools and memory, then RAG, guardrails and human approval, then multi-agent orchestration, durable execution and testing.

## Project structure

```
.
├── agents/
│   ├── agent1.py             # Memory & basic tools
│   ├── agent2.py             # RAG, guardrails & human-in-the-loop
│   ├── agent3.py             # Multi-agent orchestration (sequential / parallel / nested / worker)
│   ├── crash_resume_demo.py  # Durable execution: crash a run and resume it
│   └── test_agent2.py        # Mock test for agent2 (no LLM or server needed)
├── reports/                  # Markdown reports generated by agent3.py
├── gide.txt                  # Quick command cheat sheet
├── pyproject.toml            # Project metadata & dependencies (managed by uv)
└── uv.lock
```

## Requirements

- Python **3.13+**
- [uv](https://docs.astral.sh/uv/) package manager
- A **Google Gemini API key**
- A **Firecrawl API key** (only for `agent3.py` web research)

## Setup

1. Install the dependencies:

   ```bash
   uv sync
   ```

2. Set your environment variables. Put them in a `.env` file at the project root, or set them in your shell:

   ```env
   GEMINI_API_KEY=your-gemini-key
   FIRECRAWL_API_KEY=your-firecrawl-key
   AGENTSPAN_SERVER_URL=http://localhost:<port>
   ```

   On Windows (cmd) you can also use `set GEMINI_API_KEY=...`, or in PowerShell `$env:GEMINI_API_KEY="..."`.

3. Start the Agentspan server (keep it running in a separate terminal):

   ```bash
   uv run agentspan server start
   ```

## The agents

### 1. `agent1.py`: memory and basic tools

A concise personal assistant that shows the basics:

- **`@tool`** turns a Python function (`get_current_time`) into a tool the model can call. The docstring tells the model what the tool does.
- **`ConversationMemory(max_messages=50)`** keeps the last 50 messages so the agent remembers earlier turns.
- A simple chat loop using `run(...)`. Type `q` to quit.

```bash
uv run agents/agent1.py
```

### 2. `agent2.py`: RAG, guardrails and human-in-the-loop

A customer support bot backed by a mock database and a small knowledge base:

- **RAG**: the `search_knowledge_base` tool retrieves the matching support doc (refund policy, shipping, account) before the agent answers.
- **Tools**: `lookup_order` reads an order from `MOCK_DB` (try order `A100`).
- **Human-in-the-loop**: `process_refund` is declared with `@tool(approval_required=True)`. When the agent calls it, the run pauses with a `WAITING` event and asks you `Approve? (y/n)` in the terminal.
- **Guardrails**: `safe_support_request` is an input guardrail. Prompts containing phrases like `ignore`, `system prompt` or `jailbreak` are blocked (`OnFail.RAISE`).
- **Structured output**: replies are validated against the `SupportResponse` Pydantic model (`stage`, `successful`, `message`).
- **Streaming**: `start(...)` + `handle.stream()` lets the script react to each event (tool call, tool result, waiting).

```bash
uv run agents/agent2.py
```

Example prompts:

- `What is your refund policy?`
- `I want a refund for order A100`

### 3. `agent3.py`: multi-agent orchestration

A research and analysis system built from several agents:

| Agent | Role |
|---|---|
| `researcher` | Searches the web (`search_web`) and reads pages (`fetch_page`) via Firecrawl, writes notes with a `## Sources` section |
| `writer` | Turns the notes into a structured article |
| `editor` | Polishes the article for publication |
| `market`, `risk`, `financial` | Analysts covering market, risk and financial angles |
| `analysis_team` | Runs the three analysts **in parallel** and synthesizes one brief |

Agents are chained with the `>>` operator, so each agent's output becomes the next one's input.

When you run it, you choose a mode:

| Mode | Pipeline |
|---|---|
| `sequential` | `researcher >> writer >> editor` |
| `parallel` | `analysis_team` (market + risk + financial at the same time) |
| `nested` (default) | `analysis_team >> researcher >> writer >> editor` |
| `worker` | Registers `nested_pipeline` as a long-running worker that executes tasks sent by the server |

The final output is saved as Markdown in `reports/<mode>-<topic-slug>.md`, for example [reports/nested-nvidia-stock.md](reports/nested-nvidia-stock.md).

```bash
uv run agents/agent3.py
# Mode ['nested', 'parallel', 'sequential', 'worker']: nested
# Topic: NVIDIA stock
```

### 4. `crash_resume_demo.py`: durable execution

Shows that Agentspan stores workflow state on the server, so a run survives a crash of the client process.

1. Set `MODE = "start"` and run the script. Copy the printed **Execution ID**.
2. Kill the script (Ctrl+C) partway through the 10 slow steps.
3. Set `MODE = "resume"`, paste the ID into `EXECUTION_ID`, and run it again. It continues from the step where it stopped instead of starting over.

```bash
uv run agents/crash_resume_demo.py
```

### 5. `test_agent2.py`: testing agents with mocks

Uses `agentspan.agents.testing` (`mock_run`, `MockEvent`, `expect`) to test `support_agent` with scripted events, so no real LLM call or server is needed. It checks that the run completed, that the answer mentions "refund", that the right tool was called with the right arguments, and that there were no errors.

```bash
cd agents
uv run test_agent2.py
# or: uv run pytest agents/test_agent2.py
```

## Key concepts covered

- Tools (`@tool`), tool credentials and timeouts
- Conversation memory
- Retrieval-augmented generation (RAG)
- Input guardrails against prompt injection
- Human approval for sensitive actions
- Structured outputs with Pydantic
- Event streaming
- Sequential, parallel and nested multi-agent pipelines
- Workers, durable execution and resuming runs
- Mock-based agent testing
